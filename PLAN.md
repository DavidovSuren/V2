# Version 2.0 — полный план доработки

Правила, 13 этапов (0–12). Готовый код из «Приложения А» лежит в
`internal/payouts/` и `internal/subscription/subscription.go`, макеты из
«Приложения Б» — в `docs/design/` (номер файла = номер экрана).

Продолжение работы: «Продолжай с этапа N по PLAN.md».

## Решения, принятые перед началом (2026-09-26)

План писался до коммита `ed39f5e` (ветка `dev`: веб-админка `/admin` с логином
и паролем, редактирование вопросов/заданий из БД, премиум-агенты с кабинетом
`/partner`). Владелец решил:

1. Ветка `version-2-premium` сделана **от `dev`** — работа из `ed39f5e` сохраняется.
2. Премиум-агенты **заменяются партнёркой из этапа 1**: агентские коды работают как
   обычная реферальная ссылка, кнопка «Стать агентом» и раздел «Агенты» в админке
   убираются, кабинет `/partner` становится веб-версией кошелька партнёра для всех
   (вход по реферальному коду и паролю, пароль задаётся в профиле Mini App).
3. Админка заявок на вывод (этап 4) — **раздел «Выводы» в существующей веб-админке
   `/admin`** (вход по `ADMIN_LOGIN`/`ADMIN_PASSWORD`), а не отдельный вход по
   `ADMIN_TG_ID`. `ADMIN_TG_ID` остаётся для уведомлений админу в бот.

Вопросы и задания в `dev` редактируются через админку и хранятся в БД —
правило «не менять вопросы/задания» относится к коду и `cmd/server/data/*.json`
(исходный банк и `models.Questions`), а не к правкам владельца в админке.

## Правила для всех этапов

**Нельзя менять (ни текст, ни порядок, ни количество):**
- Вопросы анкеты: `internal/models/questions.go` — все 21 вопрос (пол + 16 диагностических + 4 открытых),
  их тексты, варианты ответов и ID. Меняется только **внешний вид** экрана анкеты (этап 9).
- Банк заданий: `cmd/server/data/tasks_male.json` и `tasks_female.json` — по 365 заданий, тексты,
  категории, `why`. Не удалять, не переименовывать, не перегенерировать.
- Планировщик: `internal/scheduler/` и эталон `internal/scheduler/testdata/node_parity.json`.
- Логика уровней и XP: `internal/leveling/` (кроме добавления новых констант, если этап просит).
- Алмаз на 100 уровне и подарок 6 месяцев Premium — остаются как есть.
- Готовые файлы из Приложения А (`internal/payouts/`, `internal/subscription/subscription.go`) — использовать, не переписывать.
- Промокод `LVL100` (он же `100LVL`, регистр и пробелы не важны): открывает **всё сразу** — 100 уровень, алмаз, все награды
  (сколько бы их ни стало), все 365 заданий отмечены пройденными, 6 месяцев Premium (а значит и доступ после пробного периода,
  уровни всех участников и контакты). Применяется один раз на человека. Это **не оплата**: запись в `subscription_payments`
  не создаётся, пригласившему комиссия не начисляется. Любой этап, который меняет награды, доступ или подписки,
  обязан сохранить это поведение и обновить тест `TestPromo100LVL`, проверяя оба написания.

**Как работать:**
- Архитектура та же: Go 1.22, серверный рендер HTML, формы и ссылки, без SPA. JS — только маленькие
  скрипты в `web/static/`. Новые зависимости Go не добавлять без крайней необходимости.
- Схема БД: только добавлять (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, `CREATE TABLE IF NOT EXISTS`)
  в `internal/db/db.go`. Ничего не удалять из существующих таблиц — в проде живые данные.
- Все деньги — целые рубли (`int`). Все даты для правил «день/месяц» — по Москве (`Europe/Moscow`).
- Каждое изменение поведения — с тестами (`internal/handlers/flow_test.go` для сквозных сценариев).
  Старые тесты, которые проверяют отменённое поведение (скидки, агентские коды), — переписать под новое.
- Все тексты интерфейса — на русском, на «ты», без восклицательных знаков в системных сообщениях.
- После каждого этапа: `go vet ./...`, `go test ./...`, коммит «Этап N: <кратко>».

## Этап 1. Новая партнёрская программа
Цена для приглашённого всегда полная (Plus 369 ₽, Premium 888 ₽). С каждой оплаты приглашённого
(включая продления) пригласившему — процент в кошелёк, по его тарифу на момент оплаты и числу **разных**
приглашённых, оплативших **до** этой оплаты (платящий сейчас не считается):

| Тариф пригласившего | Оплативших до этого: 0–9 | 10 и больше |
|---|---|---|
| Plus 369 ₽ | 5% | 10% |
| Premium 888 ₽ | 20% | 50% |
| Нет активной подписки | 0% | 0% |

Округление `int(price*pct/100 + 0.5)`: 369×5% = 18, 369×10% = 37, 888×20% = 178, 888×50% = 444, 369×50% = 185.

1. `internal/referrals`: `Prices`, `TierOrder`, `TierNames`, `BoostThreshold = 10`, `Rates`,
   `CommissionPct(referrerTier, priorPaying)`, `CommissionAmount(pricePaid, pct)`; удалить скидки и `PremiumAgentCommissionPct`.
2. БД: `subscription_payments.commission_pct`, `subscription_payments.charge_id` + уникальный индекс.
3. `store.PriorPayingReferralsCount(referrerID, excludeUserID)`.
4. `(a *App) activateSubscription(userID, tier, chargeID)`: продление того же тарифа от старой даты, запись оплаты,
   начисление в кошелёк («Партнёрский доход: <Имя>, <Plus|Premium>»), идемпотентность по `charge_id`,
   сообщение пригласившему «+185 ₽ в кошелёк: <Имя> оформил(а) Premium».
5. Убрать скидки из профиля. 6. Убрать премиум-агентов (см. решение 2). 7. Тесты: 12 оплат Plus у Premium-пригласившего
   (10×74 ₽, затем 2×185 ₽), пригласивший без подписки → 0, пригласивший Plus → 18 ₽, продление → комиссия снова, счётчик не растёт.

## Этап 2. Настоящая оплата через Telegram
Переменные `PAYMENT_PROVIDER_TOKEN`, `PAYMENT_CURRENCY` (RUB|XTR), `STARS_PRICE_PLUS`, `STARS_PRICE_PREMIUM`,
`PUBLIC_URL`, `MINIAPP_SHORT_NAME`, `PAYMENTS_TEST_MODE`. Bot API: `GetMe`, `CreateInvoiceLink`,
`AnswerPreCheckoutQuery`, `SetWebhook` (secret_token), `SendMessageWithWebAppButton`.
`POST /subscribe`: тест-режим → активировать сразу; есть токен/XTR → инвойс и `Telegram.WebApp.openInvoice`;
иначе — «Оплата временно недоступна». `POST /telegram/webhook` (секрет = первые 32 hex sha256(BOT_TOKEN)):
pre_checkout (проверка payload и суммы), successful_payment (идемпотентно), `/start КОД` → кнопка web_app на `PUBLIC_URL/?ref=КОД`.
`GET /?ref=КОД` → cookie `v2_ref`. Тесты: без секрета 401, неверная сумма ok=false, двойной charge_id, без токена не активирует.

## Важно знать (для владельца)

- Удержание 13% делает тебя налоговым агентом (6-НДФЛ, уплата в срок); с выплат физлицам обычно платятся ещё
  страховые взносы. Альтернатива — выплаты только самозанятым.
- Черновик соглашения (этап 5) показать юристу до запуска.
- Для 6-НДФЛ нужны данные получателя; если бухгалтер скажет, что без ФИО/ИНН нельзя — вернуть поля в форму вывода
  (`payouts.ValidINN` уже есть).
- Промокод `LVL100` даёт 6 месяцев Premium бесплатно и партнёрские 20–50% — раздавать осознанно.
- Telegram требует продавать цифровые товары за Stars; оплата картой через ЮKassa может нарушать правила —
  поэтому есть `PAYMENT_CURRENCY=XTR`.
