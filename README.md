# Версия 2.0 — Telegram Mini App

Персональная игра по созданию улучшенной версии себя за 365 дней.
Одно действие в день. Прогресс. STREAK. XP. Уровни. Достижения. Сообщество.

---

## Описание

**Версия 2.0** — Telegram Mini App, в котором пользователь:

1. Проходит анкету (пол + 16 диагностических вопросов по 8 направлениям жизни + 4 открытых вопроса) и получает персональный план на 365 дней.
2. Каждый день выполняет **одно** конкретное задание — задания подобраны отдельно для мужчин и для женщин (365 на каждого пола) и персонализированы под слабые места по анкете.
3. Отмечает состояние в дневнике, копит XP, растит уровень (0–100) и STREAK.
4. На 100 уровне получает алмаз на аватар и 6 месяцев Premium в подарок.
5. Видит других участников в «Сообществе»; с подпиской 888 ₽/мес — видит их уровень, бейджи и алмаз, плюс раздел «Контакты» (реферальная сеть + добавленные по @username друзья).
6. Приглашает друзей по реферальной ссылке: чем больше успешных оплат — тем выше скидка для новых приглашённых (20% → 35% → 50%). Премиум-агентские коды (выдаёт только владелец) дают держателю 50% комиссии с каждой оплаты в «Кошелёк».

Главный принцип продукта: не список из 20 задач, а **одно действие в день**.

## Архитектура

```
v2/
├── frontend/            # Telegram Mini App — статические файлы
│   ├── index.html         # разметка + стили (тема Telegram)
│   ├── api.js              # fetch-клиент к backend
│   └── app.js               # весь клиентский JS
└── backend/              # Node.js + Express + PostgreSQL
    ├── server.js            # Express app (отдаёт и API, и frontend/)
    ├── db.js                 # пул pg + схема (создаётся при старте)
    ├── routes/                # onboarding, tasks, diary, progress,
    │                           # community, subscriptions, admin, reports
    ├── lib/                    # scheduler, leveling, referrals, telegram...
    ├── cron/                    # напоминание 15:15 МСК, недельный/месячный отчёт
    ├── data/                     # сгенерированные банки заданий (365 × 2 пола)
    └── scripts/
        └── generate-tasks.js      # генератор банка заданий
```

Backend хранит данные по-настоящему (PostgreSQL): пользователей, прогресс, рефералы,
кошелёк, платежи. Frontend обращается к нему через `fetch` с заголовком
`Authorization: tma <initData>` (реальная Telegram-аутентификация с проверкой
подписи) либо через `X-Debug-*` заголовки в режиме разработки вне Telegram.

## Как запустить

### 0. PostgreSQL

Нужен доступный инстанс Postgres (локально — например, через Docker:
`docker run -d -e POSTGRES_DB=v2 -e POSTGRES_USER=v2 -e POSTGRES_PASSWORD=changeme -p 5432:5432 postgres:17`).
Схема (таблицы, индексы) создаётся автоматически при первом запуске сервера —
ничего накатывать вручную не нужно.

### 1. Backend

```bash
cd backend
npm install
cp .env.example .env
# впиши в .env:
#   DATABASE_URL  — строка подключения к Postgres, например
#                   postgres://v2:changeme@localhost:5432/v2
#   BOT_TOKEN     — токен от @BotFather
#   ADMIN_TG_ID   — твой Telegram user id (узнать у @userinfobot) —
#                   только этот аккаунт может выдавать премиум-агентские коды
node scripts/generate-tasks.js   # один раз — генерирует data/tasks_*.json
node server.js
```

Сервер поднимется на `http://localhost:3000` и одновременно отдаёт API (`/api/*`)
и статический frontend (`/`, `/app.js`, `/api.js`) — для локальной разработки
этого достаточно, отдельный сервер для фронтенда не нужен.

### 2. Доступ из Telegram

Telegram требует HTTPS-адрес для Mini App. Варианты:

- **Прод**: задеплой backend (Amvera, Railway, Render, VPS + PM2/systemd) —
  получишь постоянный HTTPS-адрес.
- **Быстрый тест**: HTTPS-туннель к локальному backend, например
  `ssh -R 80:localhost:3000 serveo.net` (адрес меняется при каждом перезапуске —
  `backend/scripts/tunnel-supervisor.js` поднимает туннель и сам обновляет
  кнопку меню бота при обрыве, полезно для разработки).

Дальше в [@BotFather](https://t.me/BotFather) или напрямую через Bot API
(`setChatMenuButton`) укажи этот HTTPS-адрес как Web App для кнопки меню бота.

### 3. Деплой на Amvera

В корне репозитория уже лежит `amvera.yaml` (окружение Node.js, ставит
зависимости из `backend/`, генерирует банк заданий при сборке, запускает
`backend/server.js`). База данных — отдельный сервис PostgreSQL в Amvera
(«Базы данных» → создать кластер), приложение подключается к нему по
`DATABASE_URL`, схема создаётся автоматически при первом старте.

**Секреты и переменные окружения задаются только через панель Amvera**
(раздел «Переменные и секреты» → «Добавить переменные или секрет»),
**`.env` в репозиторий не коммитится** (репозиторий публичный — реальные
`BOT_TOKEN` и пароль от БД в нём сразу же смогут увидеть и угнать). Нужно задать:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | `postgres://<user>:<пароль>@<внутренний адрес БД>:5432/<база>` — внутренний адрес (вида `amvera-<аккаунт>-cnpg-v2-rw`) и пароль показывает сама Amvera после создания кластера БД |
| `BOT_TOKEN` | токен от @BotFather (как **секрет**) |
| `ADMIN_TG_ID` | твой Telegram user id (узнать у @userinfobot) |
| `DEV_ALLOW_FAKE_AUTH` | `false` — в проде debug-заголовки должны быть выключены |
| `PORT` | `3000` (совпадает с `containerPort` в `amvera.yaml`) |

После деплоя останется применить переменные (Amvera перезапустит контейнер)
и один раз выставить HTTPS-адрес Amvera как Web App в `setChatMenuButton`
бота — как описано в пункте 2 выше.

### 3. Если frontend хостится отдельно от backend

Пропиши перед `<script src="api.js">` в `index.html`:
```html
<script>window.V2_API_BASE = 'https://your-backend.example.com/api';</script>
```

## 8 направлений развития

1. **Внешность** — уход за собой, уверенность
2. **Стиль** — одежда, гардероб, аксессуары
3. **Тело** — движение, спорт, сон (разные задания для мужчин и женщин)
4. **Деньги** — финансовая дисциплина
5. **Отношения** — коммуникация, первый шаг
6. **Окружение** — люди и пространство вокруг
7. **Карьера** — навыки и рабочие цели
8. **Образ жизни** — привычки, творчество, новый опыт

## Анкета и персонализация

По каждому направлению — два диагностических вопроса: субъективная самооценка
(шкала 1–10) и поведенческий вопрос (частота). Чем ниже средний балл в
направлении — тем выше его приоритет: план на 365 дней строится через
weighted round-robin (`backend/lib/scheduler.js`), так что слабые по анкете
направления встречаются раньше и чаще, а весь банк из 365 заданий
проходится ровно один раз за год.

4 открытых текстовых вопроса в конце анкеты не влияют на приоритеты —
это качественный контекст ("что мешает стать лучшей версией себя" и т.п.).

## Уровни, XP, достижения

- Прогресс: `completed / 365 × 100%`. Уровень = `floor(progress%)` — ровно
  100 уровней, 100 уровень и алмаз только после 365/365.
- XP — отдельная "игровая" валюта (не влияет на уровень): база за задание +
  бонус за стрик, плюс бонусы за анкету/еженедельный/ежемесячный отчёт.
- 8 бейджей: стрик без пропусков (7/30/180/365 дней) + уровень (25/50/75/100,
  последний — алмаз). Видны другим только с подпиской 888 ₽/мес.

## Дневное задание и пропуск

Одно действие в день. «Пропустить» не теряет задание — оно остаётся тем же
и на следующий день (план просто занимает больше календарных дней при
пропусках), но обнуляет текущий стрик.

## Подписки и рефералка

- `plus369` (369 ₽/мес) и `premium888` (888 ₽/мес — доступ к «Сообществу» с
  уровнями/бейджами и разделу «Контакты»).
- Скидка новым приглашённым зависит от числа уже оплативших рефералов
  пригласившего: 1–3 → 20%, 4–10 → 35%, 11+ → 50%.
- Премиум-агентские коды выдаёт только владелец (`ADMIN_TG_ID`) через
  `POST /api/admin/grant-premium-agent`. Приглашённые по такому коду платят
  полную цену, а держатель получает 50% в «Кошелёк» (`GET /api/wallet`).

Оплата подписки остаётся симуляцией — реальный платёжный шлюз
(Telegram Payments / ЮKassa) не подключён, это сознательно оставлено на
будущее, как и в исходном MVP.

## Известные ограничения

- «Контакты» — это реферальная сеть + добавление по `@username`, а не импорт
  телефонной книги (Telegram Mini Apps не дают к ней доступа).
- БД — PostgreSQL (`backend/db.js`), масштабируется горизонтально на несколько
  инстансов backend без дополнительных изменений (в отличие от файловой SQLite).
- Push-уведомления (15:15 МСК) и еженедельные/ежемесячные сообщения бота
  работают только при заданном `BOT_TOKEN` и постоянно запущенном сервере.
