# Версия 2.0 — Telegram Mini App

Персональная игра по созданию улучшенной версии себя за 365 дней.
Одно действие в день. Прогресс. STREAK. XP. Уровни. Достижения. Сообщество.

---

## Описание

**Версия 2.0** — Telegram Mini App, в котором пользователь:

1. Проходит анкету (пол + 16 диагностических вопросов по 8 направлениям жизни + 4 открытых вопроса) и получает персональный план на 365 дней.
2. Каждый день выполняет **одно** конкретное задание — задания подобраны отдельно для мужчин и для женщин (365 на каждого пола) и персонализированы под слабые места по анкете.
3. Отмечает состояние в дневнике, копит XP, растит уровень (0–100) и STREAK.
4. На 100 уровне получает алмаз на аватар и 6 месяцев Premium в подарок.
5. Первые 3 дня пользуется бесплатно, дальше — подписка Plus 369 ₽ или Premium 888 ₽ в месяц (оплата через Telegram).
6. Видит рейтинг недели в «Друзьях»; с Premium — уровни, награды и алмазы всех участников, плюс «Мои контакты» (реферальная сеть + добавленные по @username).
7. Приглашает друзей по реферальной ссылке и получает процент с каждой их оплаты в «Кошелёк» (5–50%, см. ниже); 15-го числа выводит деньги на карту.

Главный принцип продукта: не список из 20 задач, а **одно действие в день**.

## Архитектура

Backend на **Go 1.22** с серверным рендерингом HTML (без SPA/JSON API) —
одиночный бинарник, встраивающий шаблоны, статику и банк заданий через `go:embed`.

```
v2/
├── cmd/server/
│   ├── main.go                # entrypoint, go:embed для web/ и data/
│   ├── data/                    # банк заданий: tasks_male.json / tasks_female.json (365 × 2)
│   └── web/
│       ├── templates/
│       │   ├── layout.html        # общий HTML-каркас
│       │   ├── partials/nav.html    # нижняя навигация
│       │   └── pages/*.html          # по шаблону на экран
│       └── static/
│           ├── style.css              # вся тема Telegram + компоненты
│           └── bootstrap.js            # единственный fetch() во всём приложении (см. ниже)
├── internal/
│   ├── auth/         # подписанные session-cookie поверх Telegram initData
│   ├── db/            # database/sql + lib/pq, схема создаётся при старте
│   ├── store/           # весь доступ к БД (репозиторий)
│   ├── handlers/          # HTTP-хендлеры, по файлу на раздел
│   ├── scheduler/           # персонализация плана (weighted round-robin)
│   ├── leveling/              # уровень/прогресс/XP
│   ├── referrals/               # тарифы и проценты партнёрской программы
│   ├── payouts/                 # правила вывода 15-го, НДФЛ, проверка карты
│   ├── cardcrypt/               # шифрование номеров карт (AES-256-GCM)
│   ├── quotes/                  # цитата дня
│   ├── reminders/               # время напоминаний
│   ├── achievements/              # разблокировка бейджей
│   ├── reports/                     # еженедельный/ежемесячный отчёт
│   ├── telegram/                      # проверка initData, Bot API
│   └── cron/                            # напоминание 15:15 МСК + отчёты
├── go.mod / go.sum
└── Dockerfile
```

### Почему нет SPA / почти нет JS

Вся навигация — настоящие серверные HTML-страницы: обычные `<a href>` и
`<form>`, без единого fetch для данных приложения. Единственное
исключение — технический нюанс платформы: Telegram передаёт `initData`
(подпись пользователя) только через `Telegram.WebApp.initData` в браузере,
сервер не может получить её на первый запрос без участия JS. Поэтому
`web/static/bootstrap.js` на первом заходе (только когда сессии ещё нет —
см. `#bootstrap-target` в `welcome.html`) шлёт `initData` на `POST
/auth/bootstrap`, сервер проверяет подпись (HMAC, алгоритм Telegram) и
заводит подписанную cookie — дальше вся работа идёт без единого fetch.
Модалки (подтверждение, "почему", поздравления) — нативный HTML `<dialog>`
с парой строк JS на открытие/закрытие, тоже без ajax.

## Как запустить

### 0. PostgreSQL

Нужен доступный инстанс Postgres (локально — например, через Docker:
`docker run -d -e POSTGRES_DB=v2 -e POSTGRES_USER=v2 -e POSTGRES_PASSWORD=changeme -p 5432:5432 postgres:17`).
Схема (таблицы, индексы) создаётся автоматически при первом запуске сервера.

### 1. Сервер

```bash
cp .env.example .env
# впиши в .env: DATABASE_URL, SESSION_SECRET, BOT_TOKEN, ADMIN_TG_ID;
# локально удобно PAYMENTS_TEST_MODE=true и DEV_ALLOW_FAKE_AUTH=true
go run ./cmd/server
```

Сервер поднимется на `http://localhost:3000` и сразу отдаёт и HTML-страницы,
и статику — отдельный фронтенд не нужен, всё в одном бинарнике.

Локальный тест без Telegram: `DEV_ALLOW_FAKE_AUTH=true` в `.env` позволяет
завести сессию через `curl -X POST /auth/bootstrap --data-raw "debug:<любой_id>"`
вместо реального initData.

### Тесты

```bash
go test ./...
```

Сквозные тесты HTTP-хендлеров (`internal/handlers/flow_test.go`) ходят в
настоящий PostgreSQL и без `TEST_DATABASE_URL` пропускаются. Каждый тест
работает в своей временной схеме и удаляет её за собой:

```bash
TEST_DATABASE_URL="postgres://v2:changeme@localhost:5432/v2?sslmode=disable" go test ./...
```

`internal/scheduler/testdata/node_parity.json` — эталон, снятый со старого
Node-планировщика (коммит `14bc237`): Go-версия обязана выдавать те же
веса и тот же порядок 365 заданий.

### 2. Доступ из Telegram

Telegram требует HTTPS-адрес для Mini App. Локально — HTTPS-туннель
(например, `ssh -R 80:localhost:3000 serveo.net`), в проде — задеплоенный
адрес (см. ниже). Дальше в [@BotFather](https://t.me/BotFather) или через
Bot API (`setChatMenuButton`) укажи этот адрес как Web App для кнопки меню бота.

### 3. Деплой на Amvera

`amvera.yaml` в корне настроен на сборку через `Dockerfile` (multi-stage:
`golang:1.22` → `alpine`, бинарник ~15 МБ, шаблоны/статика/банк
заданий встроены через `go:embed` — больше в образе ничего не нужно).

**Секреты и переменные окружения задаются только через панель Amvera**
(раздел «Переменные и секреты» → «Добавить переменные или секрет») —
`.env` в репозиторий не коммитится. Нужно задать:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | `postgres://<user>:<пароль>@<внутренний адрес БД>:5432/<база>` — адрес и пароль показывает сама Amvera после создания кластера БД |
| `SESSION_SECRET` | случайная строка (как секрет) |
| `BOT_TOKEN` | токен от @BotFather (как секрет) |
| `ADMIN_TG_ID` | твой Telegram user id (узнать у @userinfobot) |
| `DEV_ALLOW_FAKE_AUTH` | `false` — в проде debug-режим должен быть выключен |
| `PORT` | `3000` (совпадает с `containerPort` в `amvera.yaml`) |
| `PAYMENT_PROVIDER_TOKEN` | токен ЮKassa из @BotFather → Payments (как секрет) |
| `PAYMENT_CURRENCY` | `RUB` или `XTR` (Telegram Stars; тогда нужны `STARS_PRICE_PLUS`, `STARS_PRICE_PREMIUM`) |
| `PUBLIC_URL` | https-адрес приложения — при старте на него ставится вебхук бота `/telegram/webhook` |
| `MINIAPP_SHORT_NAME` | короткое имя Mini App из @BotFather (`/newapp`) — для реферальных ссылок |
| `PAYMENTS_TEST_MODE` | `false` — в проде подписка активируется только после оплаты |
| `CARD_ENC_KEY` | ключ шифрования номеров карт для вывода (как секрет): `openssl rand -base64 32`. Без него вывод выключен |
| `TAX_WITHHOLD_PCT` | `13` — НДФЛ, удерживаемый при выводе |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | вход в веб-админку `/admin` (заявки на вывод — раздел «Выводы») |

После деплоя отдельно проверь в панели Amvera поле порта приложения
(в разделе Networking/домена) — оно должно быть `3000`, а путь health-check
— `/api/health`.

## 8 направлений развития

1. **Внешность** — уход за собой, уверенность
2. **Стиль** — одежда, гардероб, аксессуары
3. **Тело** — движение, спорт, сон (разные задания для мужчин и женщин)
4. **Деньги** — финансовая дисциплина
5. **Отношения** — коммуникация, первый шаг
6. **Окружение** — люди и пространство вокруг
7. **Карьера** — навыки и рабочие цели
8. **Образ жизни** — привычки, творчество, новый опыт

## Анкета и персонализация

По каждому направлению — два диагностических вопроса: субъективная самооценка
(шкала 1–10) и поведенческий вопрос (частота). Чем ниже средний балл в
направлении — тем выше его приоритет: план на 365 дней строится через
weighted round-robin (`internal/scheduler`), так что слабые по анкете
направления встречаются раньше и чаще, а весь банк из 365 заданий
проходится ровно один раз за год.

4 открытых текстовых вопроса в конце анкеты не влияют на приоритеты —
это качественный контекст ("что мешает стать лучшей версией себя" и т.п.).

## Уровни, XP, достижения

- Прогресс: `completed / 365 × 100%`. Уровень = `floor(progress%)` — ровно
  100 уровней, 100 уровень и алмаз только после 365/365.
- XP — отдельная "игровая" валюта (не влияет на уровень): база за задание +
  бонус за стрик, плюс бонусы за анкету/еженедельный/ежемесячный отчёт.
- 10 наград на экране «Путь»: «Первый шаг», стрик без пропусков (7/30/180/365
  дней), уровень (10/25/50/75/100 — последний «Алмаз»). Видны другим только
  с Premium.

## Дневное задание и пропуск

Одно действие в день. «Пропустить» не теряет задание — оно остаётся тем же
и на следующий день (план просто занимает больше календарных дней при
пропусках), но обнуляет текущий стрик.

## Пробный период и подписки

- Любой новый пользователь — 3 дня полного доступа с момента регистрации.
  Потом без активной подписки открыты только профиль, тарифы (`/plans`),
  оплата, кошелёк, соглашение, тема и выход; анкету можно пройти всегда.
- `plus369` (369 ₽/мес) и `premium888` (888 ₽/мес — плюс уровни и награды всех
  участников и «Мои контакты»). Повторная оплата того же тарифа продлевает
  его от текущей даты окончания.
- Оплата — `POST /subscribe` создаёт инвойс Telegram (RUB через провайдера
  с чеком 54-ФЗ или Telegram Stars при `PAYMENT_CURRENCY=XTR`) и открывает
  его через `Telegram.WebApp.openInvoice`. Подписка активируется только по
  `successful_payment` в вебхуке `/telegram/webhook` (идемпотентно по
  `charge_id`); `pre_checkout_query` сверяет сумму. `PAYMENTS_TEST_MODE=true`
  активирует подписку сразу — только локально.
- Промокод `LVL100` (он же `100LVL`) — 100 уровень, все награды, 365/365 и
  6 месяцев Premium; один раз на человека; это не оплата и дохода
  пригласившему не приносит.

## Партнёрская программа и вывод

Приглашённые всегда платят полную цену. С каждой их оплаты (включая
продления) пригласившему в кошелёк идёт процент — по его тарифу на момент
оплаты и числу **разных** приглашённых, уже оплачивавших до этого
(`internal/referrals`):

| Тариф пригласившего | 0–9 оплативших | 10 и больше |
|---|---|---|
| Plus 369 ₽ | 5% | 10% |
| Premium 888 ₽ | 20% | 50% |
| Нет активной подписки | 0% | 0% |

Реферальная ссылка — `t.me/<бот>/<MINIAPP_SHORT_NAME>?startapp=КОД` (или
`t.me/<бот>?start=КОД`). Старые агентские коды работают как обычная ссылка.

Вывод (`internal/payouts`): только 15-го числа по Москве, раз в месяц, от
500 ₽, весь баланс, на карту банка РФ — пользователь вводит только номер
карты (проверка Луна, хранится зашифрованным `CARD_ENC_KEY`). С суммы
удерживается НДФЛ `TAX_WITHHOLD_PCT` (13%).

## Админка и кабинет партнёра

- `/admin` — вход по `ADMIN_LOGIN`/`ADMIN_PASSWORD`: обзор (пользователи,
  пробный период, платящие, выручка за месяц, заявки на вывод), вопросы,
  задания, пользователи и раздел **«Выводы»** — заявки с полным номером
  карты, «Выплачено» / «Отклонить» (деньги возвращаются в кошелёк),
  CSV за месяц для бухгалтера. О новой заявке бот пишет `ADMIN_TG_ID`.
- `/partner` — кабинет партнёра в браузере: вход по реферальному коду и
  паролю, который задаётся в кошельке Mini App.

## Напоминания

Время выбирается в профиле (07:00–22:00, шаг 30 минут, по умолчанию 15:15
МСК): бот присылает задание, цитату дня и кнопку «Открыть». В 21:00 — «Стрик
N дней сгорит в полночь», если стрик от 3 дней и день не закрыт. Плюс
сообщения за день до конца пробного периода и 15-го — о дне вывода.

## Пользовательское соглашение

Текст — `cmd/server/web/templates/pages/terms.html` (страница `/terms`, открыта без
входа), редакция — `handlers.TermsVersion`. Без согласия пользователь не создаётся;
при смене `TermsVersion` все увидят экран «Мы обновили соглашение».
**Текст — черновик: согласовать с юристом до запуска.**

## Что сознательно оставлено как заглушки

- Выплаты по заявкам владелец проводит вручную (админка отмечает «Выплачено»).
- AI-генерация карточки «Ты через 365 дней» и фото-эволюция (фото при
  регистрации больше не загружаются).

## До запуска — проверить с юристом и бухгалтером

- Удержание 13% делает владельца налоговым агентом (6-НДФЛ, уплата в срок);
  с выплат физлицам обычно платятся ещё страховые взносы. Для 6-НДФЛ нужны
  данные получателя — если без ФИО/ИНН нельзя, вернуть поля в форму вывода
  (`payouts.ValidINN` уже есть).
- Текст соглашения (`/terms`) — черновик.
- Telegram требует продавать цифровые товары за Stars — оплата картой через
  ЮKassa может нарушать правила; переключатель `PAYMENT_CURRENCY=XTR`.

## Известные ограничения

- «Контакты» — это реферальная сеть + добавление по `@username`, а не импорт
  телефонной книги (Telegram Mini Apps не дают к ней доступа).
- Напоминания и сообщения бота работают только при заданном `BOT_TOKEN`
  и постоянно запущенном сервере; кнопка «Открыть» — при заданном `PUBLIC_URL`.
